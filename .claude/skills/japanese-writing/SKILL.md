# 日本語の文章規範

日本語で書いて残る文章を書くとき、推敲するときは、この規範に従う。

チャットの返答は対象外で、グローバル設定（Claude Code は `~/CLAUDE.md`、Codex は `~/AGENTS.md`）の口調設定に従う。表や太字をどれだけ使うか、どういう節で組むかといった書式は、呼び出し元のskillが決めた指定を優先する。このskillが決めるのは文の書き方である。です・ます調かである調かも呼び出し元に従い、1つの文書の中で混ぜない。

## 書く前に決めること

書き始める前に、次の4つを決める。決めないまま書くと、読み手が出来上がった文書を見てから「これは要らない」「順番を変えて」と指示し直すことになる。

- 誰が読むか、どこまで公開されるか。読み手が判断に使わない要素（自分用のメモ、読み手が知らない固有名、社外に出せない実例）は最初から入れない
- 分量。読み手がその文書に使える時間から決める（朝会の前に1分で読む、レビューで5分かけて読む）。文字数や項目数はそこから逆算した目安として使う（「改善点は1つ」「2000字程度」）
- 結論。冒頭に置く一文を先に書く。経緯や根拠はその後に回す
- 根拠。何を読んで書いたのか（ファイル、ログ、会議の記録）を特定し、読み手が必要なら辿れるようにしておく。数値や固有名は根拠を見て書き、記憶や補完で埋めない。確認していないことは推定と書く

説明・提案・まとめは、冒頭に結論を一文だけ置き、その後の本文を「今どうなっているか → 理想はどうか → 差分 → だから課題はここにあると判断 → 打ち手（検討した選択肢と、これを選んだ理由）」の順で組む。読み手が検証したいのは結論ではなく、現状認識と理想のどこがズレているかなので、この順なら部分的に訂正できる。理想・現状・差分・課題の層には打ち手の語を入れず、打ち手の節を消して読んでも理想〜課題が成り立つかで点検する。

短い文章（スライドの1枚、表のセル、PR本文の要約）を書くときも、いきなり短く書かない。まず読み手が隣にいるつもりで、長さを気にせずに口頭でどう説明するかを組み立てる。何がどうなるか、なぜそうなるか、どんな場合に起きるかを具体的に言えるようにしてから、重複と前置きを削る。口頭で組み立てるのは内容を決めるためで、完成した文を話し言葉にするためではない（型2の「話し言葉の混入」は完成文にも当てる）。

## 文書の種類による違い

以下の規範は、文書が説明文か、著者の語り口がある記事かで当て方を変える。どちらに当たるかは呼び出し元のskillの指定に従い、指定がなければ読み手と公開先から決める。

説明文（報告・PR本文・仕様・手順書）は、読み手がそのまま判断や作業に使う。

- 比喩は使わない
- 行為の主体を書く。「方針が決定された」ではなく「チームで方針を決めた」と書く。前の文から主体が明らかなら、毎文に主語を足さなくてよい
- 条件と結果を1対1で書く。「適宜対応する」ではなく「失敗したら3回まで再試行する」と書く

著者の語り口がある記事（ブログ・LT・振り返り）は、書き手が何を考えたかを読み手が追うものである。

- 場面転換・感想・前置きの文は、情報を持っていなくても残す。「では、このとき裏で何が起きていたのかを見ていきます」「全部説明しなくても把握してくれていて、最高です」は削らない
- 素朴な感想と、「〜かもしれない」「ちょっと面倒だった」のような迷いは残す
- 体験に無理に教訓を付けない。「真理」「境地」「美学」「深淵」「結晶」のような大げさな熟語で語らない
- 冒頭に結論の一文を置かなくてよい。最初の節で、何の話をどういう順で書くかが分かればよい
- 削ってよいのは、中身の代わりに置かれた言い回しだけ。比喩で意味が決まらない文は言い直す。「論証の穴」と「読み手の負荷」の規則（用語の揺れ、指示語、定義していない中心語など）は記事にも当てる

## AIくさい文の3つの型

LLMが書いた文章は、次の3つの型に当てはまりやすい。どの型で書いても、書き手が何を判断したのかが文面に残らない。

### 1. 否定・対比・留保から入り、言いたいことを直接書かない

「AではなくB」「〜だけでは足りない」「もちろん〜だが」で文を始め、主張を後ろに回す型。否定する相手（A）を読み手が考えていないなら、その否定は要らない。

- 悪い例：「大事なのはツールを入れることではありません。使われ続けることです」
- 良い例：「ツールは、導入したあとも使われ続けているかで評価します」

否定が要るのは、読み手が実際に抱きそうな誤解を正すときである。そのときは否定する命題を「」で正確に書き出し、否定する根拠を一文添える。

### 2. 抽象語や比喩的な動詞で、何をするのかが分からない

動詞が比喩になっていて、誰が何に何をするのかが特定できない型。書き手に比喩を使った意識がないまま混ざるので、比喩のつもりがない文も点検する。

- 悪い例：「迷ったら安全側に倒す」→ 良い例：「判断がつかない変更は入れずに、現状のまま残す」
- 悪い例：「課題の解像度が上がった」→ 良い例：「どの工程で止まっているかが分かった」
- 悪い例：「この設計が後から効いてくる」→ 良い例：「この設計にしておけば、項目を足すときに既存の処理を変えずに済む」

混ざる経路は3つある。

- 英語の慣用句の直訳：carry / open / expose / live in を「運ぶ」「開かれた」「露出する」「住む」と訳す。「この問いは開かれている」→「この問いにはまだ答えが出ていない」
- 無生物主語：データ・モデル・仕組みが意思を持つように書く。「データが語るのは」→「データから分かるのは」、「この仕組みが判断を支える」→「この仕組みがあると、担当者は〜を見て判断できる」
- 話し言葉の混入：口頭の議論では通じる動詞（「効く」「刺さる」「筋がいい」「いい感じに」）をそのまま書く

次の語が比喩として使われていたら疑う。「PRを閉じる」「ファイルを開く」のように字義どおりの動作なら問題ない。

- 動詞：倒す、効く、刺さる、寄せる、閉じる、開く、運ぶ、住む、露出する、立ち上がる、浮かび上がる、壊れる、溶かす、潰す、踏み込む、添える、収斂する
- 様子を装う副詞：静かに、黙って、地味に
- 位置や役割を表す名詞：入口、土台、主役、構図、線引き、落とし穴、事故、地続き、輪郭
- 質感や理解を装う語：解像度、手触り、肌感、温度感、熱量、腹落ち、メンタルモデル、筋がいい、いい感じに
- 英語の直訳：「〜した瞬間」（the moment）、「〜を示唆している」（suggest）

判定は2段で行う。まず、その述語を初めて読む人が字義どおりの動作を思い浮かべるなら疑う。次に、動作の主体と対象を具体的な語で言い直してみる。言い直せたら、その言い直しを書く。言い直せないなら、その文は何を言っているのか決まっていないので、削るか内容を決めてから書き直す。

比喩ではないが、「分離」「管理」「対応」「保証」のような漢語の動詞1語で、実際の動きや条件を言った気になる文もこの型に入る。同じ2段の判定で、何が・いつ・どう動くかを言い直す。

- 悪い例：「認証と権限確認を分離する」→ 良い例：「ログインしているかはAPIがリクエストを受けた時点で確かめ、どのデータを読めるかは各処理で判定する」
### 3. 短文・対句・読点・名詞化で、内容より印象を強く見せる

- 短い文や体言止めを連ねて調子を作る：「速い。安い。壊れない。」
- 対句の決め台詞：「作って、壊して、また作る」「AではなくBだった」
- 意味の切れ目ではない位置の読点：「その判断は、まだ、早い」
- 動作を名詞に変えて「実施」「実現」「推進」で受ける：「可視化の実現を図る」→「見えるようにする」
- 本文の文と文をダッシュ（——）やコロン（：）でつなぐ。つなぐなら接続詞で論理関係を書く（箇条書きの先頭に付ける見出し語のコロンは対象外）

問いや項目を句点で区切って並べる書き方（「どこに書き、いつ見直すのか。誰が直すのか。」）は、調子を作る短文の連打には当たらない。1文にまとめ直さない。

## 空っぽな決まり文句

論点を増やさずに「ちゃんと書いている感じ」だけを出す言い回し。使わない。

- 予告と総括：「重要なのは〜である」「本稿では〜を見ていく」「まとめると」「要するに」（直前の言い換えだけのとき）「〜に他ならない」「ポイントは3つ」「一言でいうと」
- 前置き：「結論から言うと」「正直に言うと」「ここで注目すべきは」
- 締め：「〜というわけです」「〜と言えるでしょう」「いかがでしたでしょうか」「参考になれば幸いです」
- 姿勢だけの宣言：「正面から扱う」「真摯に向き合う」
- 強調だけの形容：「不可欠」「核心的」「鍵となる」「本質的」「根本的な」「非常に」「極めて」
- 何をしたかを書かない形容：「多角的」「包括的」「総合的」
- 何を書いたかを示さない動詞：「掘り下げる」「深掘りする」「言語化する」「整理する」（整理した結果を書かないとき）「触れる」
- 新しい情報を足さない接続：「〜において」「〜という観点から」「〜の側面から」、「さらに」「また」「加えて」の連打

主張の前置きはせず、主張をそのまま書く。「重要なのは、レビューを先に済ませることだ」ではなく「レビューを先に済ませる」と書く。

## 論証の穴

書き上げたら、読み手が反論しそうな点を先に潰す。

- 因果を書くときは、なぜそうなるのかを一文で添える。「手順で分けると変更が全体に波及する」ではなく「各工程が同じデータ形式を共有しているので、形式を変えると全工程に波及する」
- 別々のものを「同じ」でくくらない。原因が複数あるなら切り分け、どの打ち手がどの原因に対応するのかを書く
- 「必ず」「すべて」と書かない。条件を付けて書く（「〜の場合に限り」「〜しやすい」）
- 挙げた例が主張の全体を支えているか確かめる。一部しか支えないなら、主張の範囲を例に合わせて狭める
- 事実・推奨・可能性を書き分ける。推量や可能性を、根拠なく断定に書き換えない。「かもしれない」を削ってよいのは、本文の根拠で確定しているときだけ。原文にない動作や効果を書き足さない
- 「ただし」「とはいえ」で限定を置いたら、その後で論を進める。逆接で終えない
- 文書の中心になる語は、使う前に何を指すかを書く。一度決めた語は最後まで同じ語で通し、「AI」「ツール」「仕組み」のような広い語に言い換えない

## 読み手の負荷

- 後で参照しない識別子（ファイル名、関数名、キー名、スキル名）は出さず、その部品の役割を書く。合意事項・計画・報告は「誰が何をできるようになるか」「何がどう変わるか」で書き、変数名や関数名を主語にした要約にしない（主語がコードになっていないかを書き終えたら1回見直す）
- 新しい概念を出すときは、まずそれが何の種類か（手順なのか、データなのか、制約なのか）が分かる順で書く
- 「この2つ」「上記」のような指示語は、何を指すかが前を読み返さなくても決まる位置に置く
- 段落には1つの話題だけを置き、段落の最初の文でその段落が何の話かが分かるようにする。前の段落との関係は段落の頭の接続詞（「しかし」「実際」「であれば」）で示す
- 1つの文には1つの話を置く。仕組み・利用条件・例外・注意点は別の文に分ける。「この処理は15分で打ち切られ、事前にAPIキーの登録が要り、外部APIの応答待ちで遅くなることもある」は、実行時間の上限、事前の設定、待ち時間という別々の話なので3文にする
- 条件は、それがかかる文や表のセルのすぐ近くに置く。離れた注記にまとめると、どの説明にかかる条件なのか読み手が決められない
- 例は、行為者を主語にした動作のつながりで書く。「原因が特定され、修正された」ではなく「ログから原因を特定して、設定を直した」
- イ形容詞に「です」を付けた文（「難しいです」「多いです」）が出たら、文末だけ直さずに前後の流れごと書き直す。前後の文とつながっていないことが多い

## 冗長

- 同じ主張を言い換えて繰り返さない
- 描写の直後にその内容を要約し直さない
- 説明文には、つなぎや評価のためだけの文（「これは良いことです」）を置かない。語り口のある記事では残す（「文書の種類による違い」）
- 自問自答の演出（「なぜか。〜だからだ」）をしない。主張をそのまま書く
- 「〜という発想です」「〜と考えることもできます」のような枠を付けずに、発想そのものを書く
- 短くするために、動機・対象・条件・因果を読み手の推測に任せない。必要な長さは残す

## 短くするとき

- 縮めた結果、書き手にしか意味が分からない言い回しになっていないか確かめる。「再試行は成功保証ではない」は短いが、何が起きるのかが書いていない。「3回再試行しても、相手のサーバーが止まっていれば失敗のまま終わる」と書く
- 言葉を削っても収まらないときは、その場所で扱う話題を減らすか、構成を変える。文字を小さくしたり略語を増やしたりして収めると、読み手に解読を任せることになる
- 指定された長さでは条件を保てないときは、条件を落とさず、必要な長さか構成の変更を呼び出し元に返す

## 見出し

- 見出しは短く、その節で何を扱うかが分かる言葉にする。結論を言い切ってもよい。言い切りを避けるために、長い問いの形に書き換えない
- 「背景」「補足」のような情報のない見出しや、「〜を見直す」のような作業の手順だけの見出しにしない。記事の「はじめに」「おわりに」は慣例なので残してよい
- 「仕事」「管理」のような、読み手によって別の意味に取れる広い語を見出しに使わない
- 見出しや箇条書きは「〜しない」ではなく、目指す状態を動詞で書く。否定形だと残りの選択肢が絞られず、何をするのかが伝わらない

## 書き上げた後の点検

1. 冒頭の一文だけ読んで、結論が分かるか
2. 「空っぽな決まり文句」に挙げた言い回しで文面を検索し、出てきた箇所を書き直す。型2に挙げた語も検索し、出てきた箇所は型2の2段の判定にかけて、比喩だったものだけ書き直す
3. 否定形・対比で始まる文と見出しを探し、否定する相手を読み手が本当に考えているかを確かめる
4. 各段落の最初の文だけを順に読んで、論旨がつながるか
5. 不自然な文が残ったら、単語の置き換えを繰り返さない。何を伝えるかの組み立て（書く前に決めること）に戻って書き直す
6. 固有名・数値・引用が、根拠にした資料と一致しているか
