# 本人の文章を作る

本文を書き始める前に、[my-writing-style](../my-writing-style/SKILL.md) と [japanese-writing](../japanese-writing/SKILL.md) の両方を読み、適用する。既に同じ作業で読み込んでいれば再読は要らない。

## この入口が担当すること

1. 今回の読み手・用途・分量・出力先を、依頼と呼び出し元から確認する。指定された章立て・テンプレート・事実の採用条件を優先し、このskill独自の見出しへ置き換えない。
2. 事実の素材と文体の参考文を区別する。`my-writing-style` に従って口調ナレッジと用途に近い参考文を読み、今回合わせる書き方を選ぶ。skill自体を読み込み済みでも、新しい文章を作るときは参考文を改めて確認する。
3. 素材に基づいて本文を書く。報告・提案は、現状から目指す状態との差分と次の打ち手へつなぐ。記事は参考文に合う体験や感想の流れを保つ。
4. `japanese-writing` で曖昧さ・冗長さ・論証を点検した後、参考文に照らして本人の語り口が残っているかを確認する。規範を機械的に当てて、本人の迷いや素朴な感想を消さない。

本人の判断・実績・約束を補完しない。未確認の項目は案・未定・空欄など、用途に合う形で明示する。タスク自体が分からない場合は、書く対象や下書きを聞いてから進む。

## 既にある原稿を推敲するとき

原稿が本人の手書き、またはAIと本人が一緒に作ったものであれば、全面的に書き換えない。直すのは次の3種類に絞り、事実・数値・固有名・リンク・画像は原稿のまま残す。

- 本人の参考文には出てこない語尾・言い回し（本人が使わない一人称や終助詞、芝居がかった倒置、一文だけの段落の連打）
- `japanese-writing` の「AIくさい文の3つの型」「空っぽな決まり文句」に当たる箇所
- 論理のつながりが読み手に追えない箇所。原稿にない判断や感想を足して埋めず、原稿の中にある材料で言い直す

直した後は、どこをなぜ変えたかを数点に絞って本人に見せる。全文の再掲はしない。

## 壁打ちや音声入力の材料から組むとき

本人が音声入力で一気に渡した情報や、長い壁打ちで合意した内容から文書を作ると、出てきた材料を全部どこかに入れようとして、見出しが材料の置き場になりやすい。問題点の欄に現状・原因・結果が並列に並び、課題の欄に打ち手の方針が入る、という形で崩れる。

- 書く前に、文書で一番伝えたいこと（提案なら何をやるか）を一文で決める。材料はそれを支えるものだけ使い、会話で出たことや合意したことを全部は載せない
- 見出しごとに、その下に何を書くかを先に決める。例: 問題点は表に出ている症状、課題はその原因、打ち手は課題と1対1で対応させる。会話の中で仮に使ったラベルを、意味を確かめずに見出しへ持ち込まない
- 現状（事実）・原因・結果を区別する。原因から結果への流れは並列の箇条書きにせず、矢印などでつなぐ
- 打ち手の節は、冒頭の一文で何をやるかを書き、詳細はその下に置く
- 書き終えたときと、指摘を反映するたびに、全部の行を見出しの定義に照らして確かめる。指摘された箇所や体裁だけを直して終わらせない
- 構造に自信がないときは、壁打ちの文脈を持たない別のセッションやモデルに「見出しと中身が対応しているか、因果が並列になっていないか」を観点にレビューさせ、戻ってきた指摘を反映する

## ほかの手順から呼ぶとき

このskillが担当するのは文章部分だけ。素材収集、ファイルの生成、保存、コミット、公開（Zennなら `published: true` への変更）は呼び出し元の手順とユーザーの指定に従う。このskillの呼び出しを、書き込みや公開の追加許可として扱わない。

記事の所定の章立てなど、既存の書式へ本文を戻す。文体分析や参考文の一覧は、求められた場合だけ表示する。
